## Why plan 001 was shipped

It was the highest-leverage plan that is a real, user-facing correctness fix
the repo can fully verify itself. On the core journey (ask → answer), a
response that *finishes without text* — an empty provider reply, reasoning that
consumes the 2,048-token cap, or Stop before the first word — left the visitor
with their question, no answer, no error and no retry, because retry UI was
only rendered for `error` (`src/app/profile-chat.tsx` `Transcript`) and empty
assistant messages render nothing (`Message`). The route suite's own fixtures
(`stopped-answer`, `empty-answer`, reasoning-only answers) show such messages
occur. It directly serves `PRODUCT.md`'s "make generation failures
understandable and recoverable" and `ROADMAP.md` priority 4. It needed no
server, dependency or policy change, and unit, route and browser tests can all
exercise it deterministically with mocked streams. Plan 002 is smaller and
partly mitigated by the back/forward cache; 003 is CI hygiene; 004 is a
direction spike that depends on model behavior tests can't establish.

## Findings considered and rejected

- Unauthenticated `POST /api/revalidate`: documented decision (README, route
  comment, `docs/reliability-audit.md`); it only marks public data stale.
- No app-level history/size/rate limits on `/api/chat`: README and existing
  tests explicitly preserve SDK-valid histories; rate limiting is documented as absent.
- Missing `FREELLM_API_KEY` reaching the provider: documented intentional behavior.
- Model-rendered images/links with Streamdown's permissive `allowedLinkPrefixes`:
  only the visitor's own session can steer the model; no stored or shared content. Low.
- Timeline `key={r.company}` could collide if one employer has two non-intern
  roles: investigate only — current data uses distinct employer names.
- `@types/*` listed under `dependencies`: cosmetic, no runtime cost on Vercel.
- Framework error page on resume-service outage: the reliability audit records
  "no requirement for invented fallback content"; ISR serves the last good page.
